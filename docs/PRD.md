# PRD.md

# AI 기반 CCTV 실종자 탐지 및 실시간 알림 시스템

## 1. 프로젝트 목적

본 프로젝트의 목적은 실시간 CCTV 영상을 분석하여 실종 신고된 사람을 탐지하고, 발견 즉시 해당 장면을 캡처한 뒤 보호자 또는 신고자에게 알림을 전송하는 Python 기반 AI Computer Vision 시스템을 구현하는 것이다.

1차 MVP에서는 실제 CCTV 대신 iPhone과 Camo Studio를 이용한 웹캠 입력을 CCTV 영상처럼 사용한다. 이후 실제 CCTV 환경에서는 RTSP 입력으로 교체할 수 있도록 영상 입력 모듈을 분리하여 설계한다.

핵심 목표는 다음과 같다.

- 실시간 영상에서 사람을 탐지한다.
- 탐지된 사람을 프레임 간 추적한다.
- 얼굴이 보이면 얼굴 인식으로 실종자 여부를 판단한다.
- 얼굴이 보이지 않으면 Person Re-ID로 실종자 여부를 보조 판단한다.
- 실종자로 판단되면 현재 프레임과 해당 인물 영역을 저장한다.
- 알림 함수인 `send_notification()`을 호출한다.
- 향후 웹 서버, DB, 앱, SMS, FCM과 연결 가능한 구조로 확장한다.

---

## 2. 문제 정의

실종자 수색은 시간과 장소가 매우 중요하다. 하지만 CCTV 영상은 사람이 직접 확인하기에 양이 많고, 실시간으로 여러 영상을 계속 감시하기 어렵다.

본 프로젝트는 CCTV 영상을 AI가 자동으로 분석하여 실종 신고된 사람과 유사한 인물이 등장했을 때 즉시 알림을 발생시키는 시스템을 목표로 한다.

MVP 단계에서는 실제 운영 수준의 완전한 실종자 수색 시스템이 아니라, 다음 기술 흐름이 정상적으로 동작하는지 검증하는 데 집중한다.

영상 입력 → 사람 탐지 → 객체 추적 → 얼굴 인식 → 얼굴 미검출 시 Re-ID → 유사도 계산 → 실종자 판단 → 이미지 저장 → 알림 호출

## 3. 프로젝트 목표

## 3.1 기능 목표

- Camo Studio 웹캠 입력을 OpenCV로 수신한다.
- mp4 파일 입력도 지원한다.
- YOLO11을 이용해 사람 객체를 탐지한다.
- ByteTrack을 이용해 사람 객체를 추적한다.
- InsightFace를 이용해 얼굴 임베딩을 추출한다.
- 얼굴이 보이지 않는 경우 FastReID 또는 TorchReID를 이용해 Person Re-ID 임베딩을 추출한다.
- 등록된 실종자 이미지와 현재 탐지된 인물의 유사도를 계산한다.
- 설정된 기준값 이상이면 실종자로 판단한다.
- 실종자로 판단된 순간의 전체 프레임 이미지를 저장한다.
- Bounding Box가 표시된 이미지를 저장한다.
- 실종자로 판단된 인물 영역만 Crop하여 저장한다.
- 알림 전송을 담당하는 `send_notification()` 함수를 호출한다.

## 3.2 구조 목표

- 영상 입력 방식이 변경되어도 나머지 AI 처리 로직은 수정하지 않는 구조로 만든다.
- OpenCV Webcam 입력과 RTSP 입력을 동일한 인터페이스로 다룰 수 있게 한다.
- 탐지, 추적, 얼굴 인식, Re-ID, 매칭, 알림 기능을 각각 독립 모듈로 분리한다.
- MVP 이후 DB, API 서버, 앱 알림 기능과 쉽게 연결할 수 있도록 책임을 분리한다.

## 4. 기능 범위

## 4.1 1차 MVP 포함 범위

1차 MVP에서 구현하는 기능은 다음과 같다.

### 4.1.1 영상 입력

- Camo Studio 웹캠 입력 지원
- mp4 영상 파일 입력 지원
- 향후 RTSP CCTV 입력으로 교체 가능한 구조 설계

### 4.1.2 사람 탐지

- YOLO11 기반 사람 탐지
- 탐지 대상 클래스는 우선 `person`만 사용
- 탐지 결과에는 Bounding Box, confidence score, class 정보가 포함되어야 함

### 4.1.3 객체 추적

- ByteTrack 기반 객체 추적
- 같은 사람이 프레임마다 동일한 track_id를 유지하도록 처리
- 추적 결과에는 track_id와 Bounding Box가 포함되어야 함

### 4.1.4 얼굴 인식

- InsightFace 기반 얼굴 검출 및 얼굴 임베딩 추출
- 등록된 실종자 얼굴 이미지의 임베딩 생성
- 현재 탐지된 사람 영역에서 얼굴이 보이면 얼굴 유사도 계산

### 4.1.5 Person Re-ID

- 얼굴이 보이지 않는 경우 Person Re-ID 수행
- FastReID 또는 TorchReID 중 하나를 선택하여 사용
- 등록된 실종자 전신 또는 반신 이미지와 현재 탐지된 사람 Crop 이미지 간 유사도 계산

### 4.1.6 최종 유사도 계산

- 얼굴 유사도와 Re-ID 유사도를 분리하여 계산
- 얼굴이 있는 경우 얼굴 인식 결과를 우선 사용
- 얼굴이 없는 경우 Re-ID 결과를 보조 판단으로 사용
- 추후 정책 변경이 가능하도록 matcher 모듈에서 판단 기준을 관리

### 4.1.7 실종자 판단

- 유사도가 설정된 threshold 이상일 경우 실종자로 판단
- 동일 track_id에 대해 반복 알림이 과도하게 발생하지 않도록 최소한의 중복 방지 구조를 둔다.
- MVP에서는 메모리 기반 중복 방지만 적용한다.

### 4.1.8 이미지 저장

- 전체 프레임 캡처 이미지 저장
- Bounding Box가 표시된 이미지 저장
- 실종자로 판단된 인물 Crop 이미지 저장
- 저장 파일명에는 시간, track_id, 판단 방식이 포함되어야 함

### 4.1.9 알림 호출

- 실제 Firebase, SMS, 카카오톡, 이메일 연동은 하지 않는다.
- MVP에서는 `send_notification()` 함수만 호출한다.
- 함수 호출 시 발견 시간, track_id, 유사도, 저장 이미지 경로를 전달할 수 있는 구조로 만든다.

## 6. 사용자 시나리오

## 6.1 MVP 사용 시나리오

### 시나리오 1. 웹캠으로 실종자 탐지 테스트

1. 개발자가 iPhone을 Camo Studio로 연결한다.
2. Camo Studio 카메라가 PC에서 웹캠 장치로 인식된다.
3. Python 프로그램을 실행한다.
4. OpenCV가 웹캠 영상을 읽는다.
5. YOLO11이 영상 속 사람을 탐지한다.
6. ByteTrack이 탐지된 사람에게 track_id를 부여한다.
7. 탐지된 사람 영역에서 InsightFace가 얼굴을 찾는다.
8. 얼굴이 있으면 등록된 실종자 얼굴 이미지와 비교한다.
9. 얼굴이 없으면 Person Re-ID를 수행한다.
10. 유사도가 기준값 이상이면 실종자로 판단한다.
11. 현재 프레임과 Crop 이미지를 저장한다.
12. `send_notification()` 함수가 호출된다.

### 시나리오 2. mp4 영상으로 탐지 테스트

1. 개발자가 테스트용 mp4 영상을 준비한다.
2. 설정 파일에서 입력 타입을 `video_file`로 지정한다.
3. Python 프로그램을 실행한다.
4. OpenCV가 mp4 파일을 프레임 단위로 읽는다.
5. 사람 탐지, 추적, 인식, 저장, 알림 흐름이 웹캠과 동일하게 동작한다.

### 시나리오 3. 향후 RTSP CCTV로 전환

1. 실제 CCTV의 RTSP URL을 확보한다.
2. 설정 파일에서 입력 타입을 `rtsp`로 변경한다.
3. 입력 주소를 웹캠 번호 대신 RTSP URL로 변경한다.
4. 나머지 탐지, 추적, 인식, 저장, 알림 로직은 수정하지 않는다.

## 7. 기능 요구사항

## 7.1 영상 입력 요구사항

- 시스템은 OpenCV를 통해 영상 프레임을 읽을 수 있어야 한다.
- 입력 소스는 웹캠, mp4, RTSP로 확장 가능해야 한다.
- MVP에서는 웹캠과 mp4를 우선 지원한다.
- 영상 입력 모듈은 프레임을 반환하는 역할만 담당한다.
- 영상 입력 실패 시 오류 메시지를 출력해야 한다.
- 프레임 읽기 실패 시 프로그램이 즉시 비정상 종료되지 않도록 처리해야 한다.

## 7.2 사람 탐지 요구사항

- YOLO11 모델을 사용하여 사람을 탐지해야 한다.
- 탐지 클래스는 우선 사람으로 제한한다.
- 탐지 결과에는 다음 정보가 포함되어야 한다.
  - Bounding Box 좌표
  - Confidence score
  - Class ID
  - Class name

- confidence threshold는 설정 파일에서 변경 가능해야 한다.

## 7.3 객체 추적 요구사항

- ByteTrack을 사용하여 프레임 간 사람 객체를 추적해야 한다.
- 추적 결과에는 다음 정보가 포함되어야 한다.
  - track_id
  - Bounding Box 좌표
  - confidence score

- 동일 인물에 대해 가능한 한 동일한 track_id가 유지되어야 한다.
- 탐지 결과가 없는 프레임에서도 시스템이 중단되지 않아야 한다.

## 7.4 얼굴 인식 요구사항

- InsightFace를 사용하여 얼굴을 검출해야 한다.
- 등록된 실종자 얼굴 이미지에서 얼굴 임베딩을 추출해야 한다.
- 현재 탐지된 사람 영역에서 얼굴이 검출되면 얼굴 임베딩을 추출해야 한다.
- 얼굴 임베딩 간 유사도를 계산해야 한다.
- 얼굴이 검출되지 않으면 Re-ID 단계로 넘어가야 한다.

## 7.5 Person Re-ID 요구사항

- FastReID 또는 TorchReID를 사용하여 사람 외형 임베딩을 추출해야 한다.
- 등록된 실종자 전신 또는 반신 이미지에서 Re-ID 임베딩을 추출해야 한다.
- 현재 탐지된 사람 Crop 이미지에서 Re-ID 임베딩을 추출해야 한다.
- 얼굴이 없는 경우 Re-ID 유사도를 사용해 판단해야 한다.
- Re-ID 결과는 얼굴 인식보다 신뢰도가 낮은 보조 판단으로 사용한다.

## 7.6 매칭 요구사항

- matcher 모듈은 최종 실종자 판단을 담당한다.
- 얼굴 유사도와 Re-ID 유사도 threshold는 분리되어야 한다.
- 얼굴이 검출된 경우 얼굴 유사도를 우선 사용한다.
- 얼굴이 검출되지 않은 경우 Re-ID 유사도를 사용한다.
- 최종 판단 결과에는 다음 정보가 포함되어야 한다.
  - 실종자 여부
  - 판단 방식
  - 유사도 점수
  - track_id
  - Bounding Box
  - 저장 대상 이미지 정보

## 7.7 캡처 및 저장 요구사항

- 실종자로 판단되면 현재 프레임을 저장해야 한다.
- Bounding Box가 포함된 프레임을 저장해야 한다.
- 실종자로 판단된 사람 영역 Crop 이미지를 저장해야 한다.
- 저장 경로는 설정 파일에서 관리해야 한다.
- 저장 파일명에는 다음 정보가 포함되어야 한다.
  - 날짜
  - 시간
  - track_id
  - 판단 방식
  - 유사도 점수

## 7.8 알림 요구사항

- 실종자로 판단되면 `send_notification()` 함수를 호출해야 한다.
- MVP에서는 실제 외부 알림 서비스와 연결하지 않는다.
- 함수 호출 시 다음 정보를 전달할 수 있어야 한다.
  - 발견 시간
  - track_id
  - 판단 방식
  - 유사도 점수
  - 전체 캡처 이미지 경로
  - Bounding Box 이미지 경로
  - Crop 이미지 경로

- 알림 함수는 추후 FCM, SMS, 이메일 등으로 교체 가능해야 한다.

## 7.9 설정 요구사항

- 주요 설정값은 config에서 관리한다.
- 설정 파일에는 다음 값이 포함되어야 한다.
  - 입력 타입
  - 웹캠 장치 번호
  - mp4 파일 경로
  - RTSP URL
  - YOLO 모델 경로
  - confidence threshold
  - 얼굴 유사도 threshold
  - Re-ID 유사도 threshold
  - 캡처 저장 경로
  - 중복 알림 방지 시간

- 설정값 변경만으로 입력 소스와 threshold를 조정할 수 있어야 한다.

## 8. 비기능 요구사항

## 8.1 유지보수성

- 기능별로 모듈을 분리한다.
- main.py에는 전체 실행 흐름만 남기고 세부 로직은 각 모듈에 둔다.
- 카메라, 탐지, 추적, 인식, 매칭, 알림, 저장 기능은 각각 독립적으로 수정 가능해야 한다.

## 8.2 확장성

- 웹캠 입력을 RTSP 입력으로 교체해도 AI 처리 로직은 변경되지 않아야 한다.
- 추후 DB, REST API, Spring Boot, Flutter 앱과 연결 가능해야 한다.
- 알림 방식은 `send_notification()` 내부 구현만 바꾸면 교체 가능해야 한다.

## 8.3 안정성

- 영상 프레임 읽기 실패 시 프로그램이 즉시 종료되지 않도록 한다.
- 탐지 결과가 없는 경우에도 다음 프레임 처리를 계속한다.
- 얼굴이 없는 경우에도 Re-ID 경로로 처리를 이어간다.
- 임베딩 추출 실패 시 해당 객체만 건너뛰고 전체 시스템은 계속 실행한다.

## 8.4 성능

- MVP에서는 실시간성보다 전체 파이프라인 검증을 우선한다.
- 가능하면 1초에 여러 프레임을 처리할 수 있어야 한다.
- 추후 성능 최적화를 위해 프레임 스킵 설정을 둘 수 있는 구조로 설계한다.
- GPU가 있으면 GPU 사용을 고려하고, GPU가 없어도 최소 테스트는 가능해야 한다.

## 8.5 테스트 용이성

- 웹캠이 없어도 mp4 파일로 테스트할 수 있어야 한다.
- 각 모듈은 단독으로 테스트 가능한 구조여야 한다.
- 샘플 이미지와 샘플 영상으로 단계별 테스트가 가능해야 한다.

## 8.6 보안 및 개인정보

- MVP에서는 DB 저장과 외부 전송을 하지 않는다.
- 실종자 이미지와 캡처 이미지는 로컬 폴더에만 저장한다.
- 실제 서비스 단계에서는 개인정보 보호, 접근 권한, 저장 기간, 암호화 정책이 필요하다.
- MVP 문서에는 개인정보 처리 범위가 제한적이라는 점을 명시한다.

## 9.1 디렉터리 역할

### camera/

영상 입력을 담당한다.

- 웹캠 입력
- mp4 파일 입력
- 향후 RTSP 입력

### detector/

사람 탐지를 담당한다.

- YOLO11 모델 로드
- 사람 탐지
- 탐지 결과 변환

### tracker/

객체 추적을 담당한다.

- ByteTrack 연동
- track_id 관리
- 탐지 결과와 추적 결과 연결

### recognition/

인식 기능을 담당한다.

- 얼굴 인식
- 얼굴 임베딩 추출
- Person Re-ID 임베딩 추출

### matcher/

유사도 계산과 최종 판단을 담당한다.

- 얼굴 유사도 계산
- Re-ID 유사도 계산
- threshold 기반 판단
- 중복 알림 방지 판단

### notification/

알림 기능을 담당한다.

- `send_notification()` 함수
- MVP에서는 콘솔 출력 또는 로그 출력만 수행
- 추후 FCM, SMS, 이메일로 확장

### utils/

공통 유틸리티를 담당한다.

- 이미지 저장
- Bounding Box 그리기
- 시간 포맷 생성
- 로그 출력
- 파일 경로 생성

### config/

설정 파일을 관리한다.

- 입력 타입
- 모델 경로
- threshold
- 저장 경로

### captures/

탐지 결과 이미지를 저장한다.

### faces/

실종자 등록 이미지를 저장한다.

### tests/

단위 테스트 또는 단계별 테스트 파일을 둔다.

## 10. MVP 성공 기준

1차 MVP가 성공했다고 판단하는 기준은 다음과 같다.

- Camo Studio 웹캠 영상이 OpenCV로 정상 출력된다.
- mp4 영상 파일도 입력으로 사용할 수 있다.
- YOLO11이 영상 속 사람을 탐지한다.
- 탐지된 사람에게 ByteTrack track_id가 부여된다.
- 등록된 실종자 얼굴 이미지의 임베딩이 생성된다.
- 현재 프레임의 사람 얼굴이 등록 이미지와 비교된다.
- 얼굴이 없는 경우 Person Re-ID 비교 흐름으로 넘어간다.
- 유사도가 threshold 이상일 때 실종자로 판단된다.
- 실종자로 판단된 순간의 전체 프레임 이미지가 저장된다.
- Bounding Box 포함 이미지가 저장된다.
- 실종자 Crop 이미지가 저장된다.
- `send_notification()` 함수가 호출된다.
- 웹캠 입력을 mp4 입력으로 바꿔도 나머지 로직이 동일하게 동작한다.
- 향후 RTSP 입력으로 교체 가능한 구조가 유지된다.
- DB, 웹 서버, 앱 없이도 로컬 Python 프로그램만으로 전체 AI 탐지 흐름이 검증된다.
